## Fusion 能做什么？

Fusion 是面向 Windows 本机 Codex 桌面客户端的账号池工具。添加自有或经授权使用的账号后，可以统一查看额度、选择新会话的首选账号、排队处理并发请求，并了解本机用量。日常对话仍在 Codex 桌面里完成。

| 需要 | Fusion 提供的能力 |
| --- | --- |
| 管理多个账号 | 浏览器授权、套餐与额度展示、暂停/恢复、重新授权；当前首选卡片持续突出 |
| 按需求选择账号 | 自动、高订阅优先、低订阅优先、高额度优先、低额度优先五种策略 |
| 同时处理多个任务 | 每账号默认 4 个并发名额；繁忙时排队，未绑定的新请求可选择可用备用账号 |
| 保持多轮上下文 | 会话、响应引用、图片引用和加密上下文保持原账号 |
| 查看消耗和运行情况 | 本机累计 Token、近 7 天趋势、今日每小时使用时长、池内请求记录和 Codex 内胶囊概览 |
| 方便开启和退出 | 一键启动；关闭时恢复启用前的接入，等待在途请求并完整退出 Codex |

每个账号仍受自身套餐、模型权限、额度和上游服务状态限制。Fusion 不合并订阅额度，也不提高单账号限额。每台电脑独立运行、独立授权；当前范围是本机 Codex 账号池，不包含多供应商 API 管理或跨电脑账号同步。

## v1.0.9 的改进

- **更清楚地说明旧聊天如何继续。** 首选账号只影响新会话；关闭只恢复启用前接入。继续池内旧聊天需要重新启动账号池，并保留原账号和有效绑定。
- **移除账号前说明不可恢复的后果。** 关联旧聊天的绑定会失效，重新添加同一账号也不会恢复；暂时不用时可以选择暂停。
- **额度刷新不再锁住整个控制台。** 各账号单独显示进度，重复读取合并；全部刷新等待每个结果后汇总部分失败，不阻塞导航和正常启停。
- **发送前可以等待短期冷却。** 尚未发送的业务请求最多等待 60 秒，并计入原排队预算；当前请求区分冷却与并发等待，支持定向取消，已有会话保持原账号。
- **补充诊断与性能测量。** 手动诊断加入有限的挂件原生输入链路计数；新增只使用临时数据的大历史统计基准。它们用于定位问题，不代表挂件偶发失灵或全部卡顿已修复。

发送后的断流、超时、工具调用或执行状态不明，不会触发自动重放；收到 429 的原请求也不会自动补发。发送前部分瞬时建连失败仍只进行原有的一次有限重连。

## 安装与使用

1. 下载 [Releases 中的安装包](https://github.com/Echolzt17/Fusion/releases)。Windows 10 / 11 x64 使用同一个安装包，包含 WebView2 离线依赖；登录和请求仍需联网。
2. 保持 Codex 桌面自身已登录，并准备可用的显式代理。在 Fusion 中点击“添加账号”，通过浏览器完成授权。Fusion 授权与 Codex 自身登录分别维护。
3. 完成当前任务并保存未发送输入，点击“启动账号池”。软件检查客户端并配置接入，已有客户端完整退出后再打开，未运行时打开一次；随后新建聊天使用账号池。
4. 点击“关闭账号池”或从托盘退出时，软件恢复原接入、排空池内请求并完整退出 Codex，完成后保持 Codex 关闭。关闭主窗口仅隐藏到托盘，账号池继续运行。

**切回官方接入后，池内旧聊天不能直接改用官方账号续接。** 要继续原池聊天，请重新启动账号池；要使用官方账号，请在官方接入下手动打开 Codex，新建聊天并带入必要的任务摘要。Fusion 不迁移加密上下文。

顶部更新按钮只检查并展示说明，点击“立即更新”才下载。下载与修复材料准备期间可稍后更新；安全安装收尾开始后等待完成。账号池已关闭且已脱离时，Fusion 更新不关闭或重启独立运行的 Codex；账号池开启时先完成正常关闭，更新后保持关闭，需点击“启动账号池”才打开客户端。手动覆盖安装前，先正常关闭账号池并退出 Fusion。

## 数据与安全边界

请求路径为 **Codex 桌面 → 本机 Fusion 网关 → 原账号的上游服务**。网关默认仅监听 `127.0.0.1:18765`，使用独立本机密钥鉴权。外部 AI 请求使用当前可识别的显式代理，未取得有效代理时明确报错；AI 请求不经过 Fusion 错误报告接收服务器。

账号令牌保存在当前 Windows 用户的凭据管理器；Fusion 不读取、复制或替换 Codex / Cockpit 的登录文件。SQLite 保存账号元数据、设置、数值统计和哈希绑定，不保存对话正文、提示词、图片或完整响应。Codex 用户配置中包含本机网关密钥，请勿分享该 provider 定义。

诊断默认在本机。用户预览确认后才可上报白名单失败诊断与统计，也可仅上报数值摘要。新增挂件计数不包含坐标、窗口句柄、键盘内容或对话正文；桥接成功仅表示 Tauri 接受事件，不能证明前端已执行操作。

## 当前验证范围

核心、桌面、界面、更新和安装保护均有自动化检查，相关夹具使用临时路径和假服务。自动化通过不替代真实账号、安装升级或跨电脑验收。

仍待完成的项目包括：新版真实聊天与切换验收、部分 Win10 / Win11 组合和网络环境的持续使用、Codex 原生生图/保存/连续改图，以及挂件偶发点击或拖动失灵的现场定位。部分环境的 502 / 503、断流根因尚未全部确认。实际结果与待验收项见[维护记录](https://github.com/Echolzt17/Fusion/blob/main/docs/MAINTENANCE.md)和[验收说明](https://github.com/Echolzt17/Fusion/blob/main/docs/ACCEPTANCE.md)。

## 源码与继续开发

本仓库从 v1.0.9 起同时提供经过审查的应用源码、构建配置、锁文件、测试、字体与第三方许可说明，方便在其他 Windows 电脑继续开发。公开源码采用当前开发快照，不包含原维护机的私有 Git 历史、账号、运行数据库、诊断材料或发布私钥。

```powershell
git clone https://github.com/Echolzt17/Fusion.git
cd Fusion
npm ci
npm run check
npm test
npm run web:build
```

桌面开发需要 Rust MSVC 工具链、Visual Studio C++ Build Tools、Windows SDK 和 WebView2。完整环境配置、测试及签名发布边界见[开发指南](https://github.com/Echolzt17/Fusion/blob/main/docs/DEVELOPMENT.md)。普通开发不需要发布私钥；在新电脑使用账号池时需重新登录账号，不通过源码仓库搬运凭据。

## Fusion 是做什么的？

Fusion 是面向 Windows 本机 Codex 桌面客户端的账号池工具，适合需要管理多个自有或经授权使用的 Codex 账号的个人与小团队。添加账号后，Fusion 在本机统一处理新会话选号、并发排队、额度展示和请求统计，减少反复手动切换账号的操作。

**你继续使用熟悉的 Codex 桌面界面，Fusion 在后台管理账号和连接。** 每台电脑独立运行、独立授权；本仓库提供软件下载、更新与使用说明，源码暂不公开。

## 能带来什么效果？

| 使用场景 | Fusion 提供的能力 |
| --- | --- |
| 有多个账号，切换麻烦 | 浏览器授权添加账号，统一查看套餐、额度和状态；支持暂停、恢复和重新授权 |
| 希望按实际需求选号 | 自动、高订阅优先、低订阅优先、高额度优先、低额度优先，共五种策略 |
| 多个任务同时进行 | 每账号默认 4 个并发名额；全部繁忙时排队，未绑定的新请求可选择可用备用账号 |
| 需要多轮对话和工具调用 | 会话、响应引用和加密上下文保持原账号，避免续接时混用身份 |
| 想随时了解消耗 | 首页合计本机官方／其他接入与账号池用量，支持 7 天柱／线切换及今日每小时使用时长；Codex 胶囊仍显示池内额度和累计 |
| 希望方便接入和退出 | 一键启动并重开 Codex 加载接入；关闭或退出时恢复原接入，等待池内在途请求完成 |
| 遇到故障需要定位 | 查看请求阶段、有限传输观测与七天小时统计；手动确认上传失败记录和统计，也可仅上报数值摘要 |

多账号可为新的独立会话提供更多可用账号选择。**每个账号仍受自身套餐、模型权限、官方额度和上游服务状态限制**；不会合并订阅额度或提高单账号限额。已有会话不会因为原账号限额或故障自动迁移到另一个账号。

已适配 Codex 原生图片生成、参考图编辑及多轮引用路由，图片由 Codex 展示和保存。真实桌面生图、保存和连续改图的完整验收仍待完成，不作为已验证的交付效果。

## 使用什么技术？

Fusion 采用 **Tauri 2 + Rust + React / TypeScript** 构建 Windows 桌面应用，界面通过 IPC 调用本机后端。

| 技术层 | 工作方式 |
| --- | --- |
| 桌面与界面 | Tauri 2 管理窗口、托盘、Codex 生命周期与系统交互，React / TypeScript 呈现账号和运行状态 |
| 请求与调度 | 独立 Rust 核心，使用 Tokio / Axum 提供本机 HTTP 网关，处理 SSE 流式响应、账号调度与并发控制 |
| 授权与凭据 | 浏览器 OAuth + PKCE 授权；令牌和本机密钥保存于当前 Windows 用户的凭据管理器 |
| 本机数据 | SQLite 保存账号元数据、设置、脱敏请求记录与用量；会话相关标识以哈希绑定账号 |
| 软件更新 | 固定 GitHub 更新地址，验证版本和更新签名，准备上一版修复材料后进入安装流程 |

请求路径：**Codex 桌面 → 本机 Fusion 网关 → 对应账号的上游服务**。网关默认仅监听 `127.0.0.1:18765`，通过独立本机密钥校验来路；AI 请求不经过 Fusion 错误报告接收服务器。外部 AI 连接使用当前可识别的显式代理配置，未取得有效代理时明确报错。

Fusion 专注于本机 Codex 账号管理，不提供 VPN、远程公共中转或跨电脑账号同步。

## 稳定性怎么样？

Fusion 的稳定性设计重点是保持会话一致、控制并发，并在故障时保留可恢复状态：

- **会话固定账号**：多轮对话、工具响应及加密上下文不跨账号续接；账号不可用时明确提示。
- **发送前有限恢复**：明确属于业务发送前的部分瞬时建连故障，随机等待3—5秒后沿用原账号与代理配置快照重连一次；第二次连接最多10秒，仍受原发送阶段截止约束。15秒恢复预算不是模型生成总时限。
- **已发送请求不自动重放**：发送后断流、超时或结果不明时保留失败状态，避免重复执行工具或重复提交任务。
- **有界并发与排队**：取消、断开和超时后释放本机连接与名额；网络错误、普通5xx和断流不惩罚健康账号，授权和额度规则保持。
- **接入变更有核验**：保存最初恢复记录，检查配置冲突；关闭时恢复原接入，核验 Codex 已全部退出后保持关闭。
- **更新有签名与修复入口**：安装前验证包和版本，提供独立更新修复及官方接入救援入口；更新签名不等于 Windows Authenticode 签名。

## 安装与开始使用

1. 从 [Releases](https://github.com/Echolzt17/Fusion/releases) 选择实际已发布的版本，下载 `Fusion_版本号_x64-setup.exe`。Windows 10 / 11 x64 使用同一个安装包，包内包含 WebView2 离线依赖；登录和请求仍需联网。
2. 保持 Codex 桌面自身已登录，并准备可用的显式代理。Fusion 中点击“添加账号”，在浏览器完成各账号授权；这些授权与 Codex 自身登录分别维护。
3. 完成当前任务并保存未发送输入，点击“启动账号池”。软件检查客户端并配置接入，已有客户端退出后再打开，未运行时直接打开一次，随后新建聊天使用账号池。
4. 结束使用时点击“关闭账号池”，或从托盘退出 Fusion，软件恢复原接入并保持 Codex 关闭；点击启动账号池后再打开。关闭主窗口仅隐藏到托盘，账号池继续运行。

从 1.0.3 起，顶部更新按钮只检查并展示说明，点击弹窗“立即更新”才下载；下载和修复准备期间可选择“稍后更新”，进入安全安装收尾后不可取消。旧版本需先升级才能使用新流程。账号池已关闭时，Fusion 更新不关闭或重启 Codex；账号池开启时先保存工作，更新前恢复原接入并关闭 Codex，更新后账号池保持关闭，点击“启动账号池”才打开客户端；手动覆盖安装前先正常关闭账号池并退出 Fusion。安装失败时，可从开始菜单“Fusion 更新修复”打开已缓存的上一版修复文件。池内旧会话需重新启用账号池才能继续，不会自动改走其他账号。

## 数据如何处理？

账号令牌与本机密钥保存在 Windows 凭据管理器，不随安装包或 GitHub 仓库分发。Fusion 不读取、复制或替换 Codex / Cockpit 的登录文件，不保存对话正文、提示词、图片或完整响应；本机仅保留运行所需的元数据、哈希绑定和有限诊断。

本机用量只提取会话记录中的用量数值、时间和接入类别，必要标识以哈希去重。首次后台补读，之后每 15 秒增量更新；关闭期间的记录下次启动补读。任务时长合并并发重叠，未结束时只计至最后可确认活动；已导入累计不会因原记录归档或删除而减少，不同步到其他电脑。

诊断默认只在本机收集。用户预览确认后可上报白名单失败诊断、必要环境信息及小时数值摘要，也可选择仅统计摘要；不含账号身份、令牌、节点地址或对话正文。不上传逐条成功、取消和停止记录，这些仅以计数进入摘要。成功率比较只适用于已采集且上报的设备/时间范围，覆盖不足会标明，不代表全部用户的整体成功率。

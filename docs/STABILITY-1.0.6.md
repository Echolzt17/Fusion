# 1.0.6 稳定性迭代与观察口径

## 已实现的边界

- 网络、普通 5xx 和断流不再使健康账号暂避；401、明确限流/额度规则和原会话绑定保持。并发配置保持。
- 严格发送前连接故障最多一次3—5秒随机退避，第二次连接10秒；首次20秒、原发送截止180秒/图片600秒保持。成功连接后的正常生成不受15秒恢复预算截断。已发送/状态不明/输出/工具调用后断流不重放。
- 恢复时显示连接状态，成功只留诊断。最终传输失败按五分钟合并且保留请求引用；已读不反复亮起。授权/存储问题独立保留，不修改 Codex 客户端。
- 本地白名单包含字节、发送尝试、正文交给 HTTP 层的时间与进度、事件出现与否和实际故障版本。它不证明远端收齐正文，也不包含正文/凭据/工具参数/节点地址。
- 七天小时统计在原 kv 与日志事务中去重，保留成功/失败/取消/停止分母；旧明细淘汰不清零。统计缺口标不完整。
- 手动预览 v3 报告，可选仅统计摘要。服务端兼容旧报告/回执；小时快照取最新而不累加重复窗口。

## 分阶段使用

1. 在无在途任务时用正常关闭流程退出当前 Fusion，再安装1.0.6；保留原节点作为第一阶段对照。安装不会由本聊天强行终止日常客户端。
2. 本机及同事电脑分别观察至少两个正常使用日、累计100条业务请求，不足则标样本不足。手动预览/上报失败与统计，或修复后的仅统计报告。
3. 单独启用[主备扩展](../deploy/proxy/README.md)，记录启用时刻；保留原主节点，备用不因普通测速更快就晋升。再次按同一口径观察，避免混淆软件与节点改动。

主要比较真实失败率 `failure/(success+failure)`、发送前恢复后完成率 `reconnectRecovered/reconnectStarted`、各耗时桶和重复通知。取消/停止单列；分析时分开本机拒绝、传输、上游服务和账号问题。两台电脑分别统计，重叠报告按设备和窗口合并。统计桶的时间是请求结束小时，七天边界按小时向下取整，最早小时可能包含不足一小时的边界外数据；比较必须采用相同完整小时。

大请求持续更差才研究发送路径，并发相关失败增加才研究限流，单条线路持续异常才调整主备顺序。重新出现无法解释的180秒等待或中途断流才运行既有的限时元数据观察脚本，不常驻抓包。

## 当前未完成的实机验收

新版安装、真实桌面启停/继续对话、两台电脑长期观察和当前订阅的规则命中仍 pending。隔离的实际 Codex 内核/Mihomo 回归已经验证协议与边界，但不等于真实 OpenAI 服务及节点效果验收。不能根据弹窗变少就宣称稳定性已提升。

故障版本和发送尝试等新增字段只对升级后请求完整；旧版数据不补填。单次发送耗时包含建连、上传和等待响应头，本轮没有独立的成功 DNS/TLS 时间探针。永久写盘失败或进程异常结束可能留下无法完整恢复的统计缺口。

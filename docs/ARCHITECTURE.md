# 模块约定

## 2026-11-11 Codex 接入身份、后台额度切换与本机项目

用户本轮明确批准同一个 Codex 本地聊天后台分配额度账号。本节替代旧版“整个聊天永久固定首次账号”的 Codex 规则，不改变 Claude/API 的绑定语义，也不允许执行不明、输出后或工具调用后自动重放。

接入显示名为 OpenAI（模型厂商），底层仍使用 `personal_codex_pool` 独立 provider、个人登录识别、独立本机密钥头及原字段恢复范围。Fusion 首页另行显示实际账号池启停，不将显示名视作官方直连证明。正常恢复仍保留旧 provider 定义，旧池聊天关池后不会自动走原官方账号；有有效恢复记录时，不再以“当前已经脱离”掩盖 owned 字段外改冲突。实际内核实验证明，改用内置 openai 与全局 openai_base_url 会在恢复后把旧池 B 密文送给官方 A，正式 thread/resume 又拒绝改 provider；该不安全接入方案已撤回，不进入交付。

当前 0.167 内核默认对请求压缩，网关接收 JSON 因而须管理 `features.enable_request_compression=false`，同时移除当前 profile 对该字段的覆盖。新增可缺省的主/profile 压缩开关快照仅保存布尔配置，无凭据；旧恢复记录不扩大原管理范围。正常关闭恢复原值，外部改动保持冲突保护。自定义 provider 的 `capabilities.remote_compaction=unsupported` 已由实际内核证明可改走可读本地摘要，避免后续长聊天只剩账号专属 compaction 密文；实际 A→本地压缩 A→耗尽 A→同聊天 B 已验证。它不把已存在且来源不完整的密文历史变成可读全文。

`gateway::portable` 仅在新用户轮次、完整可读消息及已闭合函数/自定义工具调用对可重建时，将聊天绑定作为软偏好；原账号健康时保留，额度/授权/冷却不可用时按既有策略选择备用。实际 Responses Lite 的 additional_tools 声明和 configuration_update reasoning 控制原样保留，控制项不被误判为用户轮次。`Store::switch_chat_bindings` 对 thread/session 哈希做事务 CAS，并保存仅含账号 ID 的切换标记。旧 reasoning 只有在完成安全可读投影时剔除；后续工具请求依据标记移除已知旧账号 reasoning，保留当前账号的 reasoning。未知密文、compaction、服务端引用、远端附件和未完成工具链不会猜测迁移；turn 与所有硬引用绑定仍不可改。

独立 provider 的 request/stream retries 仍设为 0，并由实际内核协议检查验证。`storage::replay_guard` 对具有完整聊天/轮次身份的 Responses/压缩业务，在派发前事务保存操作/身份/完整 JSON 语义的哈希、版本、时间及所有权；对象键顺序不影响去重，不保存正文或凭据。结果不明/成功/输出后不释放；明确未派发或 HTTP 429 拒绝才可释放。七天最多两万条，满容量拒绝新派发，不淘汰尚未到期的不明执行记录。旧无身份接入策略保持；图片继续原生独立 provider 零重试与原账号引用，不用仅有图片轮次的哈希误拦同轮有意的重复生图。

官方桌面 `electron-account-renderer-state-v1` 按登录 owner 切换侧栏 globals/atoms，原生 core 本地项目目录本身可跨临时假登录读取。`src-tauri::local_projects` 只流式投影本机目录/名称/顺序并保存独立目录记忆，不复制账号 atoms、聊天或凭据，不写原生数据库。恢复走正式目录 deep link，仅在已运行、无在途且接入稳定时由用户明确动作触发，逐目录等待 native 状态回执；不会自动启动客户端、抢夺正在进行的任务或静默重发。本机历史启动器只读已有目录页、核验 UUID，再以固定 hostId=local 打开原 thread，不创建、复制或发送聊天。恢复目录、原聊天可见和实际续发分别验收。

## 2026-11-11 独立 Claude 订阅池与界面修复

用户明确批准 Claude 独立多订阅池。pool-core::claude_pool 使用既有 kv 的独立 v1 目录和会话哈希绑定，Vault 的 claude-pool/ 命名空间保存自主授权令牌，拒绝未来目录版本，无 SQLite schema 迁移。PKCE 回调与待授权状态仅存内存，续期不重放且保留安全收尾。ApiGateway 复用原生 Messages 流观察器、并发和排空，仅订阅模式按会话选定一次账号、重建 OAuth 头；API 来源路径保持。目录/模型查询与 count_tokens 不建立推理会话；工具结果和完整签名必须保留原账号。桌面 claude_commands 仅授权主窗，ApiClients 复用既有受管进程启动/关闭；独立更新和退出检查登录并排空，保持两个池关闭。新版范围覆盖下方旧版“Claude 仅官方登录”描述，不授权厂商混合池。

React 的 ClaudePoolWorkspace 复用启动、打印机、用量与额度/账号卡样式；当前版本移除常驻 ConversationHandoff 的渲染，保留已有手动交接后端，不引入自动跨账号迁移或自动发送历史。普通同账号会话照旧直续，无需首页选择。顶部胶囊长宽/文字/箭头约缩小三分之一。Codex 登录与后续凭据使用只提取身份匹配的套餐字段至独立非秘密 kv，额度失败时保留 Free 等真实已知套餐，不把缺失套餐猜成 Free。

内核 running 状态查询改为 try_lock，避免同步 IPC 等待启动锁；订阅解析放阻塞工作线程。导入弹窗展示经过秒数及后台继续。测速常驻可见，禁用专用出口时临时启动内核检查并停止，不启用出口或改变当前节点；检查时轮询渐进健康结果，可显式取消。真实客户端与用户订阅验收单独记录。

## 工作区入口与网络卡片布局（源码）

React 顶部用单一 `WorkspaceSwitcher` 下拉选择 Codex / Claude Code / API，触发器采用 Li-Deheng/shy-moth-10 胶囊、随包 Poppins 600 和三箭头动画，展开面板复用 `RecordSelector` 的 quick-panther-98 发光光带与弹性滑块；Codex 进入原订阅池，Claude Code 进入官方登录，API 页内选择目标客户端，仍通过原 IPC 执行。选择工作区或目标客户端只切视图，候选与运行接入继续分开。`RecordSelector` 的自定义触发图标和选择后收起为可选项，已有请求记录筛选保持原交互。

`NetworkCards` 将当前连接、多订阅明细和节点统一收进账单式单卡；常用操作集中，地区策略及节点排除等折叠到高级设置。账单按 Cksunandh/slippery-gecko-23 的公开预览结构本地适配，来源与许可见 THIRD_PARTY_NOTICES.md。

多订阅目录使用既有 `network/v1/state` kv 的版本 2 结构，保留旧单订阅读取及向前版本拒绝，不增加 SQLite schema 迁移。每个条目独立保存加密快照引用、Vault URL 引用、节点策略与健康；状态 DTO 只公开名称、种类、节点数、更新时间和标识。首次导入成为选中项但不自动启用；后续导入只追加。`network_select_subscription` 仅授权主窗，更新/删除 IPC 接收可选订阅 ID。选用时取消探测、等待旧 RouteLease 完整释放后切换；内核或持久化失败保留原订阅。删除当前项恢复系统出口且不自动选用其他项，删除非当前项保持原出口。不会把不同订阅的节点合并自动备用；API 来源网络方式及原账号/会话绑定保持。

内核运行世代在停止等待生命周期锁前递增；排队启动取得锁后及后端启动完成后均复核。取消调用者留下的异步启动不得在禁用、退出或订阅切换后重新启动旧内核。后台订阅更新仍只针对当前选中项，未选用项通过带 ID 的手动更新分别处理。

## 新聊天可读交接与挂件可靠交互（工作区）

`pool-core::handoff` 负责白名单历史投影、范围、预算、可读摘要和源指纹；不依赖桌面或账号凭据。`src-tauri::handoffs` 通过已核验的实际桌面内核 stdio 读取分页历史，在目标接入稳定时新建聊天；原账号密文不使用原生 fork 搬运。准备正文保存在有界、10 分钟内存缓存；现有 kv 仅保存最多 20 条阶段与关联元数据。新线程在池内首次发送前独立绑定账号；官方新线程使用官方 provider。创建和发送前重核源指纹与接入，创建身份先落盘，发送意图先落盘，结果不明或进程重启后不重试。新建、发送和打开均须明确动作；不改变一键启停、关闭后保持退出和官方救援流程。主窗独占 handoff_chats/prepare/create/send/status/cancel/open，挂件和远程来源无此权限。

挂件握手返回实例及单调修订号，窗口重建/导航使旧实例失效；开合事件、IPC 返回及缓存快照使用同一状态，前端不根据自己的请求值假定窗口已展开。原生输入只在前台、就绪时捕获，手势序号区分按下/抬起/取消；React 串行处理，忽略旧实例、重复和迟到事件，并回报接收及已完成动作。健康检查在 UI 线程核验内层保护层层级、范围和本进程 Raw Input 观察注册，外层仍只在 Codex 内置顶。收到事件而 3 秒没有回执时重建挂件，不重放原动作；隐藏/导航丢弃旧手势，不据此误判新页面失联。新增 widget_ready、widget_input_ack 只授权本地挂件；不授权账号、关闭或续接能力。诊断只含数值和相对时间。

## 工作区：账号池专用代理与节点

本次由用户独立授权，在现有“连接与设置”增加代理与节点卡组，不新增页面。`pool-core::network` 负责订阅目录、单次选中的订阅解析与地区/节点顺序、健康检查、选择、加密快照及请求租约；`src-tauri::network_kernel` 仅管理固定 mihomo 1.19.33 子进程，`network_commands` 提供主窗口专用 IPC。内核与控制接口只监听回环并分别鉴权，不更改系统代理、DNS、TUN。API 来源继续使用原有独立网络设置。

`UpstreamHttp` 的 pool_get/pool_post/pool_gateway_request 仅用于原账号池。普通 request/get/post 保留系统代理语义，供 API 来源和订阅首次下载使用。每次受管业务捕获不可变节点身份和内核实例，原请求及有限发送前重连保持同一节点；`RouteLease` 直到响应完整读取或取消才释放。网关租约由 Audit 持有，授权、额度及重置卡调用由读取作用域持有；无隐式重放或直连降级。无凭据健康探测与真实业务结果分开统计。

内核使用单个 HTTP 入站，按内部身份的 IN-USER 规则直接映射节点，未匹配拒绝，不依赖可变自动组。关闭账号池不停止专用网络；退出或更新先冻结新的 IPC/后台工作、完成原客户端关闭及请求排空，再停止内核。订阅替换和出口模式切换等待旧租约结束；自动选择仅影响后续请求。进程以隐藏且挂起方式创建，加入 kill-on-close Job 后才执行，正常停止及下次启动只清理归属核验通过的运行目录。

订阅 URL 通过 Vault 保存，节点大快照无条件 DPAPI 加密。运行配置在仅当前用户与 SYSTEM 可访问的临时目录短期解密，不能声称内核运行时全程密文；原始内核输出直接丢弃。状态 DTO 不含地址、口令或订阅原文；本地诊断只增加内置代理来源，现有上报有限枚举将新来源映射 unknown 以保持服务器兼容。采用既有 kv 的独立版本键，无 SQLite schema 迁移。自动测试全部使用临时路径和假节点，真实订阅及客户端验收独立记录。

## 工作区：每日订阅比价与更新网络恢复

连接与设置移除重复的 Codex 接入/启停卡；订阅池的一键入口继续由首页持有。首页不再常驻展示聊天续接说明块，账号绑定、关闭与恢复规则保持，详细说明保留在仓库文档。

`src-tauri/pricing` 独立抓取固定 OpenTheRank 公开页面、解析产品/套餐/地区价格并缓存到应用数据目录，不写账号数据库或使用 AI 凭据。按电脑本地日期合并每日首次打开/返回窗口时的检查，失败保留旧价格并标记；React 的 `PricingCards` 只通过主窗 `ai_pricing` IPC 读取。一个卡片通过产品/套餐下拉承载比价，默认 Codex / ChatGPT 并说明价格属于含 Codex 的 ChatGPT 订阅。PriceAI 入口是另一张简短介绍卡，仅通过主窗 `open_pricing_website` 的固定枚举打开两个用户指定地址，不接受任意 URL。

## 工作区：独立客户端与 API 来源

用户已授权在原 Codex 账号池旁增加 Codex / Claude Code 工作区及手动 API 来源，不泛化或替换原订阅账号、调度、会话绑定。`api_sources` 用既有 kv 的独立版本化命名空间保存无凭据来源目录、检查与哈希绑定，Key 仅由 Vault 保存；无 schema 迁移。`api_gateway` 提供按客户端 / 来源 / 修订隔离的回环入口与原生 Responses / Messages 转发，保持网络方式固定、不自动重放、不记录正文。Chat Completions 只保存 / 检查，不做协议转换。

React 客户端 / 来源标签只切视图，候选与运行态分开，必须明确启用才更改接入；旧来源上下文不跨来源修订迁移。目录、最小测试、流式、工具与桌面验收状态分开，未知用量不显示为零。新 API 来源默认系统代理，可明确直连，原订阅池代理规则保持。当前真实客户端验收仍 pending，详见 API_CLIENTS.md 与维护记录。下文仅 Codex 的历史范围限制不撤销本节已明确授权的新工作区范围。

## 工作区：会话说明、独立额度刷新与发送前等待（未发布）

本轮保持 Windows 本机 Codex 账号池范围及现有分层，不新增供应商、账号同步或数据库迁移。默认首选只影响未绑定的新会话，已有会话仍由原账号及上下文绑定决定；正常关闭只恢复默认接入，池内旧聊天需要重新启动账号池并保留有效原账号/绑定。界面在正常启停之外持续说明这一点，不增加启停确认，也不承诺迁移加密上下文。移除提示明确旧会话无法续接，重新添加不会复活失效绑定，临时停用应使用暂停。

手动额度读取与全局写操作的 busy 分开，按账号合并在途读取，并逐账号显示进度。全部刷新等待每个读取结束后报告结果，部分失败不抹除已成功的卡片；读取不阻塞启停、浏览或其他账号操作。后端沿用按账号合并、最多两个额度查询和失败保留快照的规则，真正的生命周期切换及写操作互斥保持。

业务对话、压缩和图片仅在尚未取得账号名额、未准备业务授权和未发送上游时等待短期冷却。等待保留原账号亲和；无绑定时优先使用可用账号，仅无可用账号时等待可恢复候选。冷却等待受进入账号队列后最多 60 秒及既有业务队列总预算限制；暂停、需重新授权、删除、明确额度耗尽和长冷却不因此等待。模型目录保持原策略。当前请求区分冷却与并发等待，支持现有定向取消。收到 429 的请求仍直接结束，不自动补发，发送前有限重连的证据和次数不扩大。

`scheduler::QueuePhase` 只提供并发/冷却阶段回调，不依赖网关或桌面类型；网关映射到既有当前请求 phase，没有 IPC 参数或数据库结构变化。等待取消沿用入口请求所有权与任务丢弃，不产生脱离请求的后台重试。

`widget_input::trace` 为当前或最后一个鼠标表面保留一份有界数值快照，导出到现有手动诊断的 widgetInput：原生 down/up/wheel、捕获变化、前台拒绝、动作派发、事件桥接成功/失败和相对时间。无表面或诊断不可用时为 null；仅在内存保存，没有路径、窗口句柄、坐标、正文或键盘内容。诊断锁异常不阻止鼠标动作。桥接成功只表示 Tauri 接受事件，不等同于 WebView 收到或前端已完成操作；不扩大错误上报协议、不修改焦点/捕获/前台策略。

本机用量新增显式忽略的大历史临时基准，生产扫描行为保持。测量区分完整冷扫描、完整未变化扫描、独立文件核验/数值读取解码/汇总样本及测试进程工作集；各独立阶段不能简单相加，也不作为实机锁争用或客户端性能结论。

## 1.0.7 关闭保持退出与冷启动一次打开

本节替代下文关闭后重开的历史流程。普通关闭、托盘退出及更新前收尾仅调用 stop_client；关闭回调不再调用 launch。close_connection 在原接入恢复、请求排空、目标进程全部退出后再次复核配置，成功才清理恢复/重载/进程记录。已经关闭且无需恢复时，普通退出及更新均不检查、关闭或启动独立客户端。close_for_update 遇到 off 直接返回，安装前仍保留最终 detached 复核。30秒正常退出及10秒已核验残留定向结束规则保持。

prepare_for_enable 不再激活临时桌面。已有桌面时读取实际所属内核；未运行时使用系统 Windows PowerShell/Appx 读取当前用户唯一 OpenAI.Codex 包的版本、桌面入口与 AUMID，核对安装身份和包内 app/resources/codex.exe，然后通过临时字节副本执行现有隔离协议检查（商店包ACL可能拒绝直接执行）。版本/缓存证据仍绑定原包路径及内容，复制和检查前后复核源文件长度与修改时间；副本随检查结束清理。准备过程不打开客户端或改写个人登录。配置和模型检查完成后退出旧实例，再只激活一次；冷启动激活重新解析当前安装，并继续核验新窗口、用户/会话/父子链和实际内核，变化后重验，不凭安装信息放行运行进程。若实际内核仅被客户端复制到受管运行目录，且其版本、当前桌面路径及全部字节能重新生成已验证包内内核的原指纹，则在原协议证据有效时为实际路径保存同等证据，避免重复整轮协议检查；内容、版本或桌面不同仍重新检查。

更新仍先完成包/清单/空间验证和独占锁；仅账号池开启或需继续未完成的正常恢复时执行关闭收尾，安装前最终 detached 检查不变。resume.json 保持旧结构以兼容历史记录，但新写入 enabled 固定 false；新版启动仅核对版本和安装目录后标记/清理记录，忽略旧 enabled/claimed 组合，绝不调用 start_pool。安装器启动失败保留更新记录；账号池在更新完成后保持关闭，只有用户点击启动才启用并打开 Codex。协议证书沿用现有kv，并以可缺省的equivalent_key最多保留一个经完整指纹证明相同的准备路径，兼容旧记录，供下次冷启动复用；无新 IPC 参数、设置或数据库迁移。旧版发起的升级仍由旧版执行，新版接管后才使用本流程。

## 1.0.6 稳定性与持续诊断

本节替代下文 1.0.2 的 300ms/两次20s恢复规则，以及旧的网络失败暂避账号规则。并发配置、原账号/会话/加密上下文绑定保持。

`gateway::transport` 仅接受现有 is_connect() 与瞬时错误白名单；业务请求派发状态不明确、HTTP拒绝、无响应头 EOF、输出/工具调用后中断均不重放。首次连接20秒；一次3—5秒随机等待后使用同一代理快照的10秒 connector。连接成功后的等待仍受原180秒/图片600秒发送阶段截止限制；约15秒只指额外发送前恢复，绝不是模型生成总限时。取消/关闭会丢弃整个等待，没有脱离请求的后台重试；授权续期与重置卡不走此恢复路径。

传输使用共享 Bytes 的可克隆正文，计量包装保持 body size hint 和帧，不复制正文。记录每次发送至响应头/失败的耗时、有限结果、交给 HTTP 层的正文进度与时间、响应字节、输出/工具/终止事件是否出现。进度是本机生产者观测，不证明远端收齐；本轮无法把成功连接的 DNS/TLS 耗时从发送及响应头等待中独立拆出。故障版本在请求发生时保存。

`storage::reliability` 在同一日志/去重事务写入 kv 的 reliability/v1 小时数值，不新增数据库迁移。按版本/业务类型保留七天成功、失败、取消、停止、重连、恢复后完成、来源、大小与耗时分布；2000条明细淘汰不丢分母。升级覆盖、已知持久化缺口、摘要截断均标不完整；写失败恢复后保存缺口标记。永久无法写盘时不能声称有完整记录。

前端仅通过现有 IPC 读取 reconnecting 阶段和手动报告摘要。传输通知跨对话五分钟合并，最多保留2000个请求引用并明确超出数；已读不再变未读。恢复成功只留诊断。Fusion 不修改 Codex 错误界面、不发送“继续”。

报告 v3 增加闭合数值字段；服务端保持 v1/v2/v3 与原 canonical digest、回执、pending 字节。摘要可单独手动预览上传。失败仍按设备/请求去重；管理端 `/v1/admin/reliability` 对设备/小时/版本/类型取最新 snapshot，同秒取较完整计数，迟到旧报告不叠加。使用既有 reports 表，无新 schema。

代理扩展独立放在 deploy/proxy，引用已有主备，进程名与 OpenAI 域名同时匹配。只用轻量检查发现基本不可达；不轮询业务、不关闭旧连接、不复制订阅/节点凭据。线路启用和 Fusion 代码分开验收。


## 1.0.5 关闭期间退出的进程

`codex_lifecycle` 在读取进程创建时间、路径、用户和包身份前后，均检查同一进程句柄的退出信号。已发出退出信号的句柄按退出处理，不要求 Windows 继续提供镜像路径；查询失败但句柄仍存活时保留原错误，不以路径不可读、权限失败或 PID 猜测退出。覆盖当前进程捕获、子进程发现、持久恢复记录和定向结束前复核；重开窗口检测跳过已退出的候选。正常退出等待、定向结束范围、恢复记录清理事务及更新稳定性守卫保持。无数据库迁移或授权／转发／调度变更。

## 1.0.4 本机 Codex 用量与使用时段

`pool-core::local_usage` 只读当前 Codex 数据目录下的 sessions/archived_sessions；可选只读 state_5.sqlite 的 rollout_path 用于检测缺失历史，不用其会话累计或上下文快照推算消耗。解析器只解码明确事件的白名单字段，其他 payload 丢弃；逐行内存上限 1 MiB，单文件每轮处理约 32 MiB，保留未写完末行至下轮。文件头尾指纹与偏移检测重写／截断。响应标识哈希去重，归档副本不新增计数；任务标识哈希维护区间，已完成任务不因旧副本重读而重新打开。持久值仅含数值、时间、哈希及 pool/other 类别，没有正文、原始标识、文件路径或凭据。

累计从全部 usage/v1 账号数值（含已移除账号）加非池逐次事件生成；本地池事件仅用于时间趋势，不能再次加到原池累计。token_count 快照不累加；无法解析的格式、缺失历史或池累计与本地明细覆盖不同均显示覆盖不完整。7 日按电脑本地日历分日，不把旧 UTC 日总量平移或猜分。任务区间先求并集，再按本地小时归桶，单小时最多 60 分钟；进行中的任务仅计至最后活动事件，结束时修正。下次任务开始不会把上次未闭合区间跨空闲时间延长；无时长证据时显示未知，未来小时也不填零。

`storage::local_usage` 在现有 kv 的 local-usage/v1 前缀下保存事件、区间和文件游标，同一文件处理批次在短事务中一起提交；文件读取和解析在锁外完成。保留旧统计键、数据库 user_version=1 和向前版本检查。文件删除、日志淘汰及账号移除不清除此新增数值证据，没有 schema 迁移。

桌面 `usage_dashboard` 后台任务启动即扫描，之后每 15 秒执行一次，遵守更新安装工作锁，在阻塞工作线程中读取；IPC 只返回内存快照，扫描失败保留最近成功数据。新命令仅授权主窗口，挂件和远程来源不可调用；React 不读取文件或数据库。首页独立 UsageDashboard 展示累计、7 日趋势、24 小时时长、时区和覆盖状态；柱／线偏好仅保存在本机 UI 设置。现有 usage、账号卡、挂件以及请求日志的池内口径保持。

## 1.0.2 发送前建连故障的有限恢复

gateway::send_timeout 仅在 reqwest 的 is_connect() 为真且有限分类为连接拒绝、重置、中止、关闭、UnexpectedEof 或 Timeout 时，等待 300ms 后重新建连一次。已核对锁定的 reqwest 0.12.28 / hyper-util 0.1.21：该标志来自 HTTP 请求派发前的 connector 错误；没有响应头、没有可见输出或一般 network_error 均不能单独作为重连依据。泛化 Connect、DNS、TLS 校验/协议错误、代理认证/隧道拒绝不重连。底层 retry::never 和禁止重定向保持，避免错误标志对应的是内部重放/跳转后的连接。

复用同一 RequestBuilder 的可克隆内存请求，保留 Client、代理、账号授权、正文及会话头；原 lease 不释放、不重新选账号/代理、不重取令牌、不切节点或直连。不可克隆正文直接保留原失败路径。两次建连与等待共用原 180s/图片 600s 发送阶段截止，单次建连仍 20s；取消优先且无脱离请求的后台重试。成功只产生一次业务日志/计费统计，最终失败继续使用原错误分类；本次未新增重连次数诊断字段。

收到 HTTP 状态、发送后等待超时、响应头前非 connect EOF、响应读取/终止事件失败均不重放；输出和工具调用后的执行不确定性保持。此措施只缓解可确认的发送前抖动，不修复既有响应头等待 180s 或 HTTP200 后断流的全部故障。OAuth、刷新令牌及重置卡兑换路径不在本次网关变更范围。无 UI/IPC、报告协议或数据库变更；1.0.2 使用原签名与更新机制，真实节点效果待验收。

## 0.1.28 四对话并发与传输连接

入口保留 8 个处理名额，另以 Semaphore 限制最多 32 个尚未读取正文的等待者，等待最多 600 秒。登记包含入口等待，关闭排空统计直接使用登记快照，主窗把入口等待与账号等待均显示为空闲名额等待；取消先释放真实任务、正文预算和名额，再确认登记结束。完成/取消后由响应生产任务释放入口名额，不等待下游再轮询或销毁响应对象。

正文收集在独立上传锁内串行，处理与上游流仍并行，以避免多个未知长度上传各持部分预算互相等待。已知长度在有限上传时限内等待所需预算；未知长度逐块按实际字节合并许可，不预占 256 MiB 路由最大值。仍限制总原始正文 256 MiB、路由大小、块空闲 15 秒、实际上传累计 60 秒和 JSON 结构数量。上传锁/预算等待不计入上传时间，正文阶段另有 600 秒整体等待上限。许可在收到上游响应头（发送正文已结束）时释放；提取器失败、错误、取消与断开也清理，不等候整段模型输出。不会写临时正文文件或记录正文，预算仍不是 RSS 上限。

默认每账号并发 4；读取旧版无 concurrencyConfigured 标记且 concurrency=2 的设置时仅在内存按 4 使用。新版本正常保存设置时附带该内部标记，明确保存的 2、旧版其他数值、端口及策略均保留，不改变 schema 或触发启动数据库写回。业务账号排队最多 600 秒，目录仍 10 秒；已有会话和加密上下文不换账号。图片仍全局 2、每账号 1，兼占账号总名额。

外部请求仍按当前代理配置复用 Client 对象，但禁用空闲传输连接池，并设置 30 秒 TCP keepalive；每次请求建立新传输，避免旧轮次留下的过期代理连接破坏下一轮。禁止任意自动重放、改用直连或重定向。代理在当前请求中途切断连接时仍按有限诊断报告；新连接策略不能证明已解决用户真实链路的所有断流。

四路未知长度/已知长度与共享小预算、旧默认升级、有限入口队列及取消隔离回归通过；实际安装内核四路通过真实网关和公开假上游完成。官方服务、桌面 UI 四聊天、同事 Win11 及持续使用仍待新包实机验证，具体检查与构建结果见维护记录。

admission 为已接纳请求建立内存登记，只含本地请求 ID、有限操作/阶段、账号引用、匿名对话哈希及相对耗时，不存正文或凭据。service_status 返回当前登记，主窗独占 cancel_request IPC；挂件和远程来源无取消权限。取消先终止真实处理任务/上游连接，再确认登记及名额释放，禁止直接清零计数。取消已结束请求幂等，无关账号和会话绑定不变。

响应通过容量为 1 的有界通道发送，独立生产任务持续监听定向取消、服务停止和接收端关闭；客户端不再读取或下游回压时仍能清理连接。自动清理由完成、取消、断开和原有读取超时驱动，不因任务执行时间较长而强杀正常工作；取消不承诺上游任务停止或撤销计费。无数据库迁移、跨电脑共享计数或账号同步。

## 响应类型与响应头声明

RequestDiagnostic 的 responseType 保留上游 Content-Type 的原始有限分类，detectedResponseType 是可缺省的实际内容识别结果。对话只有在现有解析器收到有效 response.* / error SSE 事件后才记为 sse；目录、压缩和图片在 JSON 解析通过后记为 json。中途失败仍保留已经取得的格式证据，格式识别不代表请求成功，不根据路由、HTTP 200 或成功状态猜测格式，也不为诊断额外读取或保存正文。

主窗和挂件优先以内容识别结果显示“响应类型”，未识别时可显示明确标注来源的响应头声明，否则显示未识别或未收到响应；“响应头声明”单独保留未提供 Content-Type 等原始状态。旧日志缺少新字段时不回填实际类型。沿用原日志 JSON 和诊断导出，无 schema 迁移，不改变转发、账号绑定、取消或零自动重放规则。

## 0.1.19 启动目录检查与实际内核版本

目录 HTTP 400 使用目录接口/版本兼容性提示，不套用对话上下文或输入设置提示；内部检查返回有限错误消息、HTTP 状态与本地请求编号，便于在系统检查日志定位，不读取或输出上游错误正文。

账号移除先在现有账号 JSON 中保存 deleting，再清理 Vault，最后执行账号/绑定失效事务；deleting 不可调度、续期、恢复或重新授权，界面提示重试移除。Vault 分段删除完成前保留索引，失败或进程中断可重入，不暂存明文令牌，不新增 schema。

Windows 静态及 WinHTTP 自动代理共用完整列表解析，支持分号和空白分隔，先选目标协议的第一项，再用第一项通用候选；只选一次，不在失败后换代理或直连。model_providers 普通表和行内表均支持，生成的 provider 只在行内容器中转为行内值；启用/恢复保留外部 provider、profile 和无关设置。

卸载默认保留账号；仅用户勾选且非 UPDATE 时，在进程和接入守卫通过后，调用不初始化桌面的 --delete-app-data。清理仅指向解析后的 LOCALAPPDATA/PersonalCodexPool；拒绝目录树中的链接/重解析点，凭据只枚举目标名称并匹配本工具服务及已知账号/密钥命名（含残留分段），不读取 blob。任一失败中止卸载并显示原因类别，重试可继续；升级、Codex 与共享 WebView2 不进入此清理。

UI 自动回归先完成生产构建再开启严格端口预览服务，不把 Vite 开发服务器的 HTML 200 视为模块图已就绪；通知及读取协调器纯逻辑直接测试，独立冷页面测试仍等待真实 load、检查 JS/CSS 和当前显示版本。源码、文档及发布产物由 check:version 统一核对，历史记录保持原版本。

## 0.1.16 网络错误分类

RequestDiagnostic 新增可缺省的 networkErrorKind 有限枚举，与既有失败阶段、上游 HTTP、响应类型和代理来源一起显示和导出。通过 reqwest 判定及源错误链中标准 I/O、hyper、rustls 的类型分类连接拒绝/重置/中止、TLS、超时与传输不完整；Windows 名称解析只识别明确的 Winsock 错误码。hyper-util 0.1.21 未公开 TunnelError，代理隧道/代理认证仅按其固定叶错误文案精确匹配，比较过程不复制或保留任意错误文本；其他情况保持未确认。显式复用已锁定的 hyper/rustls 类型，无依赖版本升级。

区分 HTTP 传输错误与未收到终止事件的正常 EOF（stream_ended）。分类覆盖建连、SSE 初始校验、流式和聚合 Responses，以及共享的目录/压缩/图片响应读取；不记录原始错误、URL、代理地址、请求/响应正文或凭据。缺少 Content-Type 仍先验证有效 SSE，不把响应头缺失自动当作断流原因。旧日志缺少分类时保持未提供，不补推根因，不新增数据库 schema 或迁移。转发、取消、账号绑定、并发限制及零自动重放规则保留。

## 运行结构

内核进程核验使用句柄等待结果判断父进程是否已退出；GetProcessTimes 的退出时间只在已退出时用于限定子进程创建区间，运行中不读取其未定义值。用户运行目录同时接受 Windows FOLDERID_LocalAppData 与原 LOCALAPPDATA 布局，仍须核对父子链、创建时间、用户 SID、会话及目录，不能仅凭进程名选中或结束内核。内核候选被拒绝时只汇总目录、用户、会话或存续时间等固定原因；确实没有候选时单独说明，不把所有情况称为“等待加载”。正常重开与兼容检查共享这套规则。 0.1.15 增加目录前缀不一致的受控识别：仅在同用户、同会话及父子存续核验通过后，接受 OpenAI/Codex/bin/版本/codex.exe 布局且与当前已核验桌面 app/resources/codex.exe 逐字节一致的内核。不扫描其他目录、不读取进程环境。核验成功按两文件路径、长度及修改时间缓存，文件变化重新比较；启动、重开和残留进程恢复复用同一规则。

Codex 自动重开先执行正常 Quit，不使用 WM_CLOSE。等待池内在途请求结束后才开始退出阶段；正常退出等待 30 秒，超时只定向结束已核验属于同用户、同会话目标客户端的残留进程，再等最多 10 秒。核验句柄、创建时间、安装路径、进程归属，旧进程未全部结束不启动替代实例；新窗口及所属内核未就绪不完成切换。不注入或修改客户端。

一个 Tauri 进程同时承载桌面窗口、托盘和 Tokio 本地 HTTP 服务。关闭窗口隐藏；托盘退出会取消授权和网关。首版不创建 Windows 服务或独立后台进程。

界面 → Tauri IPC → Accounts / OAuth / Connection → Gateway / Config → Scheduler / Store / Vault。

## 关键行为

- HTTP 仅监听 IPv4 loopback。所有 API 路由要求独立本机密钥（新接入专用头、旧接入本机 Bearer），拒绝重定向，不提供 HTTP 管理端。
- `/v1/models` 返回 OpenAI `data` 和上游 Codex `models`；模型能力保持上游元数据。
- `/v1/responses` 固定上游流式且 `store=false`，流式原样透传；非流式从 `response.completed` 聚合最终响应。
- `/v1/responses/compact` 保留上游加密内容。会话、响应 ID、加密上下文的哈希绑定到账号；未知绑定报错，禁止猜测跨账号续接。
- `/v1/images/generations` 与 `/v1/images/edits` 转发当前原生 JSON 协议，不套用 Responses 的 stream/store/instructions 归一化，不代替客户端保存或展示图片。图片模型与扩展字段保留。文生图请求 32 MiB，编辑/对话/压缩请求 256 MiB；在读取正文前验证本地密钥。图片响应和单条 SSE 事件限制 64 MiB，流式 Observer 不保留最终完整响应副本。
- 真实 thread_id 优先于缓存亲和 session_id。从轮次头、白名单元数据字段合并线程/轮次绑定；图像请求必须能解析原模型轮次。上下文、响应及图片引用的账号一致性在发送前检查，相关标识仅持久化哈希，并在同一事务建立绑定；未知上游 file/generation/image-call 引用拒绝发送。完整本地图片可作为新输入，不创建上游文件代理。
- 正文入口最多 8 个处理请求和 32 个等待者；256 MiB 原始正文预算，未知长度按实际字节记账，正文收集串行避免部分预留死锁，上游请求仍并行。等待、大小、上传和结构限制及发送后预算释放见 0.1.28。预算不代表总进程 RSS。
- SSE 用字节解析，支持 UTF-8/CRLF 跨块；缺少结束事件算中断。退出流作用域即释放 lease、上游响应与诊断 guard。
- 单账号默认并发 4，旧版 2 自动按 4 使用；业务满载最多等待 600 秒，目录等待 10 秒。上游连接 20 秒、响应头/块空闲 180 秒；无整段对话总时限。
- 图片响应头及块空闲、Responses 块空闲为 600 秒，provider 流空闲同步为 600000ms；普通目录/压缩沿用 180 秒。图片全局并发 2、每账号 1，同时占用账号总名额；一个 lease 原子预留和释放全部名额。取消或服务停止释放连接和名额，但上游执行状态不作保证。
- 新会话先用持久首选，失效后才按策略重新排序；自动按有效双周期瓶颈剩余比例、可比个人订阅、负载、稳定 ID 排序。手动优先不限制候选集合，回退后不会因原账号恢复而抢回。首选并发暂满时，未绑定请求等待约 250 毫秒后可转选有名额候选；全部繁忙时业务最多等待 600 秒、目录 10 秒，原会话只等待原账号。策略、当前账号与旧 fixedAccount 软优先使用现有 kv，策略切换原子保存；设置页保存服务参数不覆盖最新策略。没有 schema 迁移。
- 1.0.6 已移除网络/普通5xx故障暂避，不因这些错误改变健康首选。401/429 仍由 account 处理授权/限流状态。所有回退均不重放已发送请求，绑定不可跨账号修改。
- 429 使用 Retry-After 秒数，缺失或无法解析时冷却 60 秒；401 标记重新授权。仅允许文首明确发送前的有限重连，不重放已发送或执行状态不明确的上游请求。
- 删除由 Scheduler 在活动计数锁内预留，原子排除新 lease；有活动请求即拒绝，取消删除会释放预留。失败后持久 deleting 状态继续排除新 lease。Store 在删除事务中将绑定哈希写为 kv 失效标记，再删除账号，不新增 schema。
- HTTP 200 中的 SSE 错误只提取白名单授权/限流/服务错误码和安全秒数，更新后续调度资格，未知错误不推断账号故障，不重放。
- 续期任务按账号加锁并独立于调用者取消；刷新成功先保存新凭据，再响应调用方。
- 正常/官方恢复指纹绑定有效接入字段的语义内容、目标路径、程序和恢复记录，允许保留无关编辑与格式变化；救援绑定原文件全文哈希及事务记录。排空结束后再次校验，变化需要重新确认。恢复记录缺失或损坏时仍可明确切回官方，不猜测原账户凭据。新启用可直接接管官方或自定义 provider，同时暂时移除当前 profile 的 provider 覆盖；仅备份接入选择字段，关闭时恢复原选择及覆盖值。当前 profile 切换或覆盖被改动后视为接入冲突；外部 provider 表及凭据不复制，auth.json 不读写。旧恢复记录可兼容升级；无恢复记录的遗留池依赖仍须显式恢复。卸载通过只读 CLI 检查当前有效接入是否依赖本程序，未选中的历史表与旧恢复记录不阻止卸载。配置已写入不等于运行中的客户端已加载，启用应用成功后由桌面生命周期正常关闭并自动重开 Codex，再新建聊天；重启失败不回滚已应用配置、不重放；正常退出超时按文首策略定向结束。关闭恢复后由桌面层正常重开客户端。
- 恢复仅检查自己拥有字段的语义内容，允许用户修改其他配置；应用指纹绑定源全文、目标路径、程序路径、端口与生成内容，参数变化要求内部重新准备后重试。普通接入备份只包含接入字段。用户明确应用救援时原配置只在原目录改名保留，不复制、不输出内容；同目录小型事务记录仅存文件名与哈希，原子写入最小官方配置并验证脱离 Fusion 后清理。
- 生图接入使用文首保留个人登录的独立本机密钥头，本机识别标记不作为授权、不会转发上游。只改自己的 provider、选择和 features.image_generation；旧备份 JSON 可向前兼容升级，保留最初恢复目标，并保存升级前受控字段以恢复中断窗口。外部冲突时停止。没有新增数据库 schema 迁移。
- compatibility 按实际协议检查放行，不再按固定桌面/内核版本号放行。桌面层复用生命周期的用户/会话/包/父子进程核验，从实际运行包路径取得桌面版本，支持包内及用户运行目录的所属内核，忽略无关 CLI；检测保留 30 秒共享缓存，启动前和重开后强制重新解析。核心在临时 CODEX_HOME/用户目录与清空的子进程环境中，用公开假登录和本机假上游检查同一 provider 配置、登录识别、本机密钥、工具声明、生成/编辑 JSON、生产网关的轮次/引用解析、保存图片与 500 不重放。版本命令 5 秒，每个场景登录识别最多 8 秒、成功/失败请求各 40 秒，超时只结束自建检查进程；无需 Node、真实配置或账号。
- 通过证据使用现有 kv，绑定检查协议修订号、实际桌面版本/路径及内核版本/路径/文件 SHA-256；没有 schema 迁移，损坏/旧协议/客户端变化自动重验。内存按文件路径/长度/修改时间复用文件指纹，避免轮询反复读取大内核；Fusion 重启仍重新计算。检查失败不覆盖旧客户端证据，不清理原接入恢复记录。image_compatibility 分开报告自动检查进度、配置、路由、同客户端上游图片证据与待实机验收；export_diagnostics 附加仅版本/检查状态/固定错误文案的 clientCompatibility，不含路径、正文、账号或凭据。历史章节的精确版本白名单在 0.1.13 被此流程替代。
- 日志不存模型输入、响应事件、令牌、原始上游错误正文。流式错误用请求编号关联。
- 终止响应事件及压缩响应只提取 usage 白名单数值；日志与用量累计在同一 SQLite 事务写入，重复写入相同现存请求 ID 不重复计数。旧日志的 usage 默认为未知，累计统计不回填旧日志或推算中断请求。
- 账号页直接调用 start_pool，后端内部准备指纹、检查模型目录并应用配置；完整重开由后端继续执行，不依赖 React。运行中切换新会话账号只改优先选择，原会话绑定优先。

## 维护方法

授权变动先改 account/oauth；协议、目录、流/压缩变动改 gateway；选号和并发变动改 scheduler；存储版本改 storage。对应测试使用本机假上游，不消耗真实账号额度。

只对需要独立验证的核心代码拆模块，不引入插件框架、微服务或第二套网关。源码版本和依赖通过 Cargo.lock、package-lock.json 锁定。

## 0.1.10 外部请求代理

`upstream_http` 是 account/oauth/resets/gateway 共用的外部 HTTP 出口。每次创建请求时在阻塞线程读取当前 Windows 用户活动连接的代理：显式静态配置优先，其次显式 PAC；没有显式系统配置时使用相应环境变量，再尝试系统自动发现。通过 WinHttpGetIEProxyConfigForCurrentUser 与 WinHttpGetProxyForUrl 获取配置，不修改注册表，不从浏览器或凭据库导入账号。分协议映射的 https= 表示目标协议，默认仍为 HTTP CONNECT 代理，不能误作到代理的 TLS；支持显式 HTTP/HTTPS/SOCKS 地址，SOCKS5 使用代理端 DNS。

外部请求必须解析出有效代理，显式关闭 reqwest 隐式代理/直连选择，再设置单一代理；不采用 NO_PROXY 或系统排除项绕过外部 AI 请求，PAC DIRECT、缺失/损坏配置、代理故障不降级直连，也不自动换代理重放。选中代理不变时复用客户端；变化时新请求使用新客户端，旧请求仍持有原连接。解析等待最多10秒、同时最多两个阻塞解析任务，原生解析设置5秒I/O超时。仅 localhost、IPv4/IPv6 loopback 使用独立直连客户端；本地密钥不发给代理。

请求诊断的 proxySource 改为本次请求选中的配置来源，新增 Windows 自动代理与本机直连分类，旧枚举可读；未解析成功为 unknown，失败阶段为 proxy_resolution。仍不能从选中配置证明代理的远端出口。不输出代理地址、凭据、原始头、请求或响应正文，无数据库迁移。WinHTTP 分配内存及会话句柄用 RAII 清理；PAC 下载不自动携带 Windows 用户凭据。

## 挂件与独立恢复

Tauri 同进程管理 pool-widget 无边框透明窗口，后端周期检查 Connection 状态管理显示/隐藏，主窗口关闭不影响挂件。收起不抢焦点；展开可交互，失焦、Escape 和再次点击收起。使用 parent_raw 创建真实 WS_CHILD，父窗口仅识别已安装 OpenAI.Codex 包的桌面主窗（当前为 app/ChatGPT.exe），不把 codex.exe 内核当桌面；由 Windows 裁剪在父客户区内。位置使用已有 kv 的 widget_position_codex，父客户区与 DPI 决定物理边界，拖动在父坐标内钳制。父窗口销毁后重建子窗口，无父窗口时隐藏，不设全局置顶。只读 widget_snapshot 在收起时仅返回摘要，展开才读取本地请求列表；账号以本地序号显示，不返回真实邮箱或上游账号 ID，不触发 OAuth、额度或重置卡请求。React 使用独立挂件入口，不挂载主控制台的网络查询副作用。

--recover-official 位于数据库、Vault 和 Tauri 初始化之前，原生确认后调用同一恢复核心。原位保留文件采用不覆盖目标的移动；救援事务允许显式续接，损坏的事务路径不被信任。可读且 schema=1 的旧恢复记录可以在验证配置脱离 Fusion 后清理，较新版本不修改；数据库不可用不阻止配置修复。正常关闭不提供绕过恢复的退出 IPC。


## 0.1.2 响应性与发布保护

Connection 的操作锁串行化变更，短时状态锁不跨网络 await；enabling/closing 明确表示转换中。状态文件检查在阻塞线程执行，共享最多 3 秒的只读缓存；完成变更立即失效。确认、应用和恢复均重新读取文件，不用显示缓存授权写入。主界面按模块独立防重入，5 秒读取超时保留旧值；不为挂起读持续新增请求。变更后作废旧结果，防止迟到响应覆盖。隐藏主窗停止详情轮询，恢复显示立即刷新；各页面均读取最近 200 条本地日志以汇总通知，不增加上游请求；重置卡首次展示账号时自动查询，同账号防重入，独立保留上次成功结果；三秒本地轮询不重复查询官方，用户刷新额度及重置入口可更新，不自动兑换。

Tauri AppManifest 为全部业务命令生成 ACL，主窗与挂件分别授权；没有远程来源授权。挂件只能调用 widget_snapshot、widget_set_expanded、widget_drag、widget_open_console。数据库/文件型桌面 IPC 使用阻塞工作线程。日志写入失败的脱敏警告保留至本次运行结束，不把后续写入成功视作已补回丢失统计，不触发请求重放。

Windows 安装模板固定到 CLI 2.12.4；旧卸载器调用前、安装覆盖前及卸载前都检查进程与有效接入。运行中或无法确认时中止，不调用 Restart Manager 强制关闭；升级不再豁免。安装过程使用新包中不初始化数据库/Vault 的只读检查入口；旧版是否支持该参数不影响前置检查。


## 0.1.3 客户端反馈修正

Responses 不再仅凭缺失或不规范的 Content-Type 拒绝成功响应；此时先限量读取并核验有效 SSE JSON 事件，再透传原始字节（保留同块后续字节），HTML/JSON 错误页不透传、不记录正文、不重放。错误只报告固定 MIME 分类。此前日志没有上游原始头，不能断言所有实际 502 均由同一原因造成，真实推理须复验。

config_apply 仅在用户预览后点击应用才执行；历史 WM_CLOSE 关窗实现已停用，统一使用文首的正常 Quit / 进程退出核验流程。正常退出后按原进程 AUMID 激活同一安装包，最多观察 20 秒窗口。返回 message/restarted 分开表示配置成功和重启结果，未关闭或未启动时界面显示警告。

## 统一通知

`src/notifications.ts` 管理本次运行最多 100 条重要通知，`NotificationCenter` 列表只显示标题、时间、次数，详情仅 OKAY。忽略启动前的历史、models、success、cancelled 和 service_stopped；这些日志原样保留。关闭中间阶段和 reloadRequired 不产生通知；close-failed 只更新同一个连接失败条件，避免事件和状态轮询双重提醒，close-complete 产生一条最终结果。请求按日志 ID 防重复，按对话哈希及错误码在连续 5 分钟内合并，已读重复不重新提醒。未知对话退回请求 ID。查询失败保留在原账号卡，登录仅通知最终成功或失败。通知不持久化、不触发重试。

RequestLog 增加可缺省的 `conversationKey`，从现有 continuity identities 选择 thread/session 绑定哈希，thread 优先；不保存原始会话标识、正文或头。继续使用原日志 JSON 列，旧记录默认空，无 schema 迁移。诊断导出同时移除此字段及账号字段。界面隐藏时暂停轮询，重新显示后从最近日志补充通知；这不是系统级推送或独立通知数据库。

## 0.1.4 自动关闭与诊断

主窗仅调用 close_pool({exitApp})；托盘与挂件的关闭按钮直接调用同一后端入口，不经 React。桌面 CloseIntent 合并重复操作并允许停止升级为退出；lifecycle 锁串行化启用/关闭及正常重启，Connection 保持 closing 直到完成。核心阶段为 restoring → draining → restarting；失败为 failed。状态提供 closePhase/closeStartedAt，界面显示活动请求与等待时间，不驱动执行。

桌面先依据 prepare_close 的恢复结果判断是否需要重载。仅需重载时，才在排空后查找并正常重开 Codex；账号池已关闭且无需恢复时不检查客户端窗口。重载失败保留恢复记录及错误，继续提供重试。

restore_for_close 仅接受 Normal，拒绝恢复记录损坏/缺失、救援事务和受控字段冲突，不自动降级 Official/Rescue。先恢复原字段并保留备份，再排空和复核；桌面正常重开 Codex后 complete_close 再次核验、原子清理恢复/重载状态并停止网关。无任务普通退出不写配置、不重开 Codex；旧重载提示本身不构成重启理由。关闭或重启失败保留备份并恢复先前监听供未切换客户端继续使用；不会重放在途请求。独立官方救援仍单独预览确认。

RequestLog.diagnostic 为可缺省字段，旧日志兼容；包含程序版本、上游 HTTP 数值、ResponseType、FailureStage、ProxySource 有限枚举，不包含原始头、错误对象、正文、代理地址或凭据。代理枚举仅说明 HTTP 客户端创建时的配置来源，不能由此断言实际路由或拦截原因。非标准 SSE 校验区分取消、停止、空响应、读取错误/超时与格式错误，校验总时限 600 秒，不因心跳无限延长。403 来源未确认，不直接判为模型权限不足。历史日志仅留在请求日志，不导入通知；新故障独立提醒。


## 0.1.5 恢复与旧聊天定义

正常恢复保留已登记的 `personal_codex_pool` provider 表，只恢复默认/profile 选择和 image_generation 原值。旧池聊天仍绑定该 provider 和原账号，关闭后不会通过原默认接入继续。兼容 0.1.4 已恢复选择却删除 provider、仍保留恢复记录的中断状态：仅从本机接管记录补回定义。`codex_retained_provider` 使用现有 kv 存储所属定义的精确片段；后续预览/应用仅接受语义匹配的保留定义，外部编辑拒绝覆盖。恢复记录保留至重载完成，重复恢复幂等；没有 schema 迁移。官方/救援入口仍独立预览确认。

请求日志默认排除 models，系统检查独立查看。诊断元数据放入折叠详情；成功 JSON 目录响应用成功状态，取消/停止用中性状态。


## 0.1.6 请求模型、对话统计与胶囊

RequestLog 的 startedAt 为 Unix 毫秒，requestedModel/responseModel 为可缺省的受限模型标识；旧记录兼容未知。Audit 在授权通过后记录请求元数据，Observer 只从 response 事件提取模型；压缩和图片读取顶层模型。既有协议字节不变，不保存事件/正文，也不改变账号绑定或重放规则。

storage/history 使用原 logs JSON 和 kv，无 schema 迁移。每次日志与账号/对话累计及 usage-seen/v1 请求去重标记同事务提交；去重标记和对话累计长期保留。首次从仍保留的历史日志建立对话累计并标记 historyPartial，初始化标记同事务提交，已有账号累计不重算。request_history 按时间/rowid 游标每页 50 条，按对话、结果和系统分类在 LIMIT 前筛选；conversations 查询独立累计，不受 2000 条明细清理影响。

固定对话摘要按 kv 主键查询；全部及最近对话摘要以 BINARY 主键范围限定 conversation-usage/v1/ 前缀，避开长期增长的 usage-seen/v1 去重键。全部摘要取出字符串后释放数据库锁，再反序列化和排序。不新增索引、schema 或统计数据副本。

request_history 是主窗和挂件共享的只读 IPC，conversation_usage 仅主窗；widget_snapshot 展开才读取对话目录，收起只读摘要。最近请求在请求发起时更新内存状态，账号分配仅更新同一请求，不允许旧请求的结束或较晚分配覆盖新选择；重启后按持久化发起时间选择最近对话。所选对话只影响展示，不能改调度绑定。

胶囊 260×36，展开 440×540，父客户区/DPI 钳制；创建后强制首次布局显示，显示失败重新尝试，定期仅调整父窗口内兄弟层级，不设置全局 topmost 或激活。关闭成功清理前端关闭/服务状态；失败统一使用“重试关闭”，原恢复保护及预览应用条件保留。

## 请求记录信息层级

`RequestRecords` 与 `RequestNavigation` 为主窗和挂件共享的只读浏览组件。一级为全部业务请求和系统检查；对话树下仅列出实际保留的对话请求、图片生成/编辑和压缩类别，累计仍在但明细已清理的对话继续保留。每请求分基本信息、用量和诊断，不生成虚构轮次或工具子记录。LilaRest 玻璃圆球保留 800ms 弹性位移；ashif_6672 树保留 0.3s grid 行展开、0.2s 背景反馈和连接线。开合与查看范围分为两个按钮，闭合内容 inert，样式局部限定并遵从减少动态效果。内容宽度 720px 起为 200px 分类列与明细两列，窄窗/挂件按需展开分类。

`request_history` 在已有参数之外接受可选 `HistoryFilter`：unknownConversation 明确筛选无对话身份，operations 指定请求类别，account/model 的 None 表示全部、空串表示缺失。模型匹配请求或返回模型；所有条件在 SQL 的 LIMIT 51 之前执行，仍返回 50 条及下一游标。`history_catalog` 扫描全部保留日志，按业务/系统分别返回对话类别计数和账号/模型选项，不使用最近 200 条通知日志或当前页推算目录。目录由已有 `conversation_usage` 和展开时的 `widget_snapshot` 返回，没有新增 IPC 权限、数据库 schema 或持久化数据种类。

主窗离开日志页、挂件收起或切换详情分类后保留浏览组件状态并暂停明细读取。普通轮询保留页码、节点与已展开请求，切换查询条件回到第一页；选择器缺失的已选条件不会静默显示为“全部”。主窗目录与明细分别报告读取失败并保留旧数据，挂件快照失败也保留已有详情。主动进入跟随模式才跟随最近请求；点击跟随对话的面包屑不会改为固定账号。显示选择只影响浏览和胶囊摘要，不改变调度与绑定。

## 0.1.8 Windows 共用离线包与 DPI

Windows x64 构建固定 x86_64-pc-windows-msvc，静态 VC 运行库；包内是官方签名的 WebView2 Evergreen x64 离线安装程序，minimumWebview2Version 与本次实际载荷 156.0.4314.56 一致。installer-webview.nsh 共用单一离线路径，普通/静默/UPDATE 均先执行维护守卫、再检查依赖；不调用在线更新、不允许忽略失败继续。--check-webview-runtime 在数据库/Vault/Tauri 初始化之前，仅调用 WebView2 Loader 并比较严格四段数字版本，返回退出码且无输出；安装后必须再次通过，超时/未知状态均拒绝完成。辅助 EXE 与依赖释放到 NSIS 私有目录，路径正确加引号；3010 仅在复核通过时继续并设置重启标志。卸载不删除共享运行时。

window_layout 管理主窗首次显示、显示器变化和 DPI 变化的物理工作区边界，按比例调整有效最小/最大尺寸；先缓存工作区签名以避免窗口事件递归，失败会失效以供重试。挂件在 UI 线程只核对宿主和 UI 线程的 DPI 模式，再从后台发起 WebView2 创建，避开 Tauri 在同步 Windows 事件处理器创建 WebView 的已知死锁；创建后检查真实父子关系与 DPI 上下文一致，不修改线程或进程 DPI。布局读取实时宿主客户区，锚点按新旧 DPI 比例转换，拖动在变化时取消以免坐标跳跃。故障通过可清除的 desktop-warning 事件进入已有通知条件去重，不重放请求。

export_diagnostics IPC 的返回值仍为路径；JSON 新增 environment（os/osBuild/architecture/webview2Version/windowScale）及 widgetWarning，可缺省/未知，不添加数据库字段或账号身份。Windows 名称从原生版本构建号识别（10.0 的 22000+ 为 Win11），不采集用户名、机器标识或配置全文。核心转发、绑定、调度、接入预览/恢复和客户端版本白名单均保持不变。

## 0.1.9 安装耗时与返回码修复

0.1.8 把离线载荷版本错误地同时用作最低运行版本，导致本机已可用的156.0.4314.50也走升级；同时遗漏了微软 WinGet 清单对该载荷定义的成功返回码。0.1.9 将功能门槛独立为110.0.1587.40（Tauri 自定义协议所需110系列能力基线，不宣称全部旧运行时均已实机验证），不以新离线包补丁号迫使已满足功能的电脑升级；最低版本的判定仍由无数据库的真实 Loader 辅助命令执行。

安装器接受0、3010及微软清单的-2147219416/-2147219187，所有这些状态均必须再次通过Loader检查；未知错误、取消、启动失败以及成功码却不可用仍拒绝继续。NSIS压缩去掉/SOLID，应用和205MiB依赖是独立块；现有运行时就绪时可跳过依赖数据，不为提取后面的应用文件而扫描整份依赖。主程序、标识、账号数据、接入和窗口适配保持不变。


## 0.1.11 启用前打开客户端与直接反馈

桌面 config_preview/config_apply 在 lifecycle 锁内先准备客户端：复用可见主窗、恢复最小化/隐藏主窗；缺少主窗时用 Windows PowerShell 读取当前用户 OpenAI.Codex 的安装清单，只激活 app/ChatGPT.exe 对应 AUMID，不误启独立 ChatGPT 包或 codex.exe 内核。启动辅助进程限时 8 秒、窗口等待 20 秒；只可终止本次创建的检查辅助进程，不终止客户端。新启动或旧检测为未知时刷新共享版本缓存，等待内核加载；仍保持原来的准确版本白名单，不跳过生图兼容检查。

预览前仅打开客户端，不启动网关或写入接入；用户取消保留原接入，应用后继续正常 Quit/进程退出核验/重开流程。预览和应用错误、应用后重开失败在当前界面直接显示，模态框内失败不被背景遮挡；按钮显示当前阶段，账号或接入状态导致的禁用显示原因。恢复所需的关闭入口不再受可用账号数限制。没有新增 IPC 命令、权限或数据库迁移。


## 0.1.12 一键启停与完整重开

start_pool({accountId?}) 立即登记 start/checking 并异步执行；同一次启动重复调用合并。lifecycle 锁从启动登记持有到最终结果，关闭/托盘退出可排队并合并。config_preview/config_apply 不再暴露 IPC，配置指纹及备份仍由核心内部处理，前端无读写文件或客户端进程逻辑。connection_status 统一返回 operation、phase、operationStartedAt，替代旧 closePhase/closeStartedAt；配置已写入到客户端核验完成之间始终为切换中。

启动内部流程：可用账号/配置检查 → 客户端准备及自动隔离协议检查 → 内部指纹/模型探测/应用 → 排空池内在途请求 → 完整退出 → 恢复本地监听 → 激活同安装包 → 新窗口和所属内核核验（变化后自动重验）→ 完成。关闭沿用先恢复接入再排空，完整退出并激活原客户端；没有主窗时也会启动恢复后的客户端，普通已关闭状态的 Fusion 退出不无故启动 Codex。

codex_lifecycle 核验当前用户 SID、会话、包身份、路径及创建时间；只跟踪由已核验客户端二进制直接派生的客户端二进制，不穿过用户 shell/工具追踪独立 CLI。正常 Quit 后有界等待，超时通过重新核对身份的进程句柄定向结束，绝不 taskkill 按名称批量结束。原主进程先消失而内核残留时，重试读取 kv 中 codex_restart_context 的版本化进程身份记录并再次核验，不凭 PID 单独结束进程；该记录与 reload/原接入恢复记录保留到最终切换核验完成，同一事务清理，无数据库 schema 迁移。

首次接入前官方直连任务由用户先结束；池内仅等待已接纳的在途请求，不宣称能识别官方直连任务或迁移历史聊天。保留原有 auth.json，不读取/替换真实登录；原登录有效时沿用，过期由官方客户端要求重新登录。独立救援仍须单独确认。

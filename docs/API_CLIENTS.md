# 多客户端与 API 来源

本功能是工作区中的新增实现，尚未打包、安装或公开发布。当前公开 1.0.9 安装包不因此自动获得新功能。真实客户端版本及官方 / 第三方来源尚需逐项验收；模型目录或本机假服务通过不代表真实客户端通过。

## 使用顺序

1. 在顶部选择 Codex 或 Claude Code；这只改变查看对象。
2. Codex 的“订阅账号池”保留原账号、额度、首选与启停规则。“API 与中转来源”管理独立 API 来源。Claude Code 的“官方登录”通过原版客户端自身登录，Fusion 不读取或保存订阅令牌。
3. 添加来源，填写名称、协议、Base URL、默认模型及 API Key。默认跟随系统代理；需要直连时按来源明确选择。编辑来源时 Key 留空表示保留原 Key。除本机回环外，接口必须使用 HTTPS，地址不得包含用户名、密码、查询参数或片段。
4. “基础检查”只请求模型目录；“实际请求测试”会发送固定的最小测试输入，可能产生少量费用。二者不自动触发流式、工具或桌面验收通过，不会后台定时生成内容探活。
5. 点击来源卡仅选择候选项。明确点击启用或切换后才更改实际接入。同一客户端一次使用一个来源，两个客户端的业务请求可以独立运行；短暂的配置 / 启停操作串行化以保护退出和更新。
6. 切换等待在途请求完成，再按目标客户端的要求恢复、配置、退出和打开。旧聊天保留原来源；跨来源另开会话，需要原聊天时切回原来源。来源停用、移除或更改实际接入配置后不允许旧上下文自动绑定到新修订。
7. 关闭 API 连接等待在途请求完成并保持对应受管客户端关闭；Codex 的原接入恢复后也保持关闭。退出 / 更新 Fusion 会先正常关闭所有受管连接，更新完成不自动重启。

正在运行、启动或待恢复的来源不允许编辑 / 删除。改动协议、地址、模型、网络方式或 Key 会建立新修订并使原修订上下文无法通过该配置继续；若仍需旧聊天，请新增来源并保留原来源。改名或临时停用 / 恢复不改变修订。删除来源后，重新添加也不会恢复旧绑定。

## 支持范围

首批原生通道为 Codex / Responses 与 Claude Code / Messages，不做格式互转。Chat Completions 来源可以保存和检查，但不能直接启用为首批两个客户端的来源。API 图片路由暂不提供；Codex API 接入期间关闭对应生图功能，正常关闭后恢复原值。Responses 压缩能否使用由来源实际支持情况决定，缺失时明确失败，不伪造上下文或迁移到另一来源。

来源 Key 仅进入当前用户 Windows 凭据管理器。客户端配置只含独立本机密钥；恢复记录用当前 Windows 用户 DPAPI 保护。SQLite 的既有 kv 使用独立版本化命名空间，没有账号数据库 schema 迁移。日志仅保存来源标识、模型、结果、时间、字节数与已确认用量等有限元数据；不保存输入、输出、原始错误正文、授权头或订阅令牌。API 记录与原订阅池记录分开。

新连接只监听 IPv4 回环，来源和修订固定，鉴权头按协议重建，不转发客户端自己的账号凭据。系统代理失败不会自动直连；选择直连也不会自动改走代理。网关禁用自动重试和重定向。上游已收到请求后的断开、取消或超时，不能据此确认未执行或未计费。

Claude Code 管理入口只使用用户已安装的原生 claude.exe，不执行 npm / cmd 包装脚本，不代为安装。启用前在临时 HOME / 配置与环境白名单中，用公开假密钥和本机假 API 验证 500、断连、部分流中断均不重放；不通过则拒绝启用真实来源。实际受管终端使用进程局部环境及会话设置，固定禁重试和回退，并排除用户 / 项目 / local settings，因此首版不加载这些 settings 内的 hooks、插件或权限配置；不修改原文件或系统环境。机器强制策略仍遵守，若破坏所需行为则隔离验证失败。官方登录入口直接调用原版客户端自身流程，不施加 API 受管配置。只管理本次创建并核验的进程；找不到可用客户端会明确失败。工具执行、签名续接和真实终端关停仍须按实际版本验收，不能仅凭进程启动宣称验证完成。

## 自动与真实验收

核心与连接配置测试使用临时 SQLite、临时配置、假凭据库和本机假上游。UI 测试只模拟 IPC。真实验收至少包含流式多轮、工具、取消、断流不重放、旧来源续接、配置冲突恢复、双客户端并行及退出 / 更新。未登录或未联调的项目继续标记待验收，维护记录记载实际执行结果。

# Fusion 正式发布与安全更新

固定仓库为 https://github.com/Echolzt17/Fusion。本轮源码与拟正式发布版本为1.0.14，包含同聊天接续修复及此前候选版的增量上报和额度胶囊。维护者已明确要求正式打包发布；实际未完成验收保持pending，使用绑定本版本源码清单及安装包的独立授权，不修改默认发布门槛。

## 使用者

普通源码提交不会使已安装客户端更新。只有新的正式签名包公开可下载、匿名下载字节核对成功并推进稳定清单后，客户端才能发现1.0.14。既有rc候选保持独立预发布，不把候选包改名为正式包。

启动与每六小时检查只查询清单，不自动下载。顶部检查展示说明，确认立即更新才下载与验签；进入安全安装收尾前可稍后更新。账号池已关闭且已脱离时不关闭或重启独立Codex；账号池开启时先恢复原接入、排空并完整退出。更新后保持账号池关闭，只有点击启动账号池才打开客户端。手动覆盖安装前先正常关闭账号池并退出Fusion。

旧混合加密agent历史或未知密文仍须保持可核验的原账号归属，不能承诺安装新版后全部旧聊天均能无损换号。真实额度耗尽、桌面和覆盖/在线升级的结果见MAINTENANCE与ACCEPTANCE。

## 维护者

1. 同步npm/Cargo/Tauri版本、说明和经过审查的公开快照，保留精确锁文件、资源、测试及许可。业务文件必须等于已核验的本机源码，不推送维护机私有Git历史。
2. 构建新的正式1.0.14安装包并沿用原签名公钥，核对包、EXE、版本、签名与文件名。发布授权绑定具体源码清单和包，真实pending记录不伪填passed。
3. 使用项目外受保护的原签名及发布材料，不输出或提交私钥、密码、令牌、DPAPI、原始账号数据或运行数据库。
4. 公开源码以核验过的远端公开main为唯一父，用非强制更新及回读确认；正式Release和v1.0.14标签绑定同一个公开源码commit，已发布版本附件不覆盖。
5. 三个白名单附件EXE/SIG/manifest公开可下载并逐字节匹配后，先推进preview.json，最后推进stable.json，再回读确认两份清单一致。公开下载、发布完成与实机全部通过分别记录。

正式端点为 https://raw.githubusercontent.com/Echolzt17/Fusion/main/updates/stable.json。正式客户端仍只接受三段数字稳定版本；更新签名不是Windows Authenticode证书，不生成替代公钥或关闭验签。
